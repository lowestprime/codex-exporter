# Codex Exporter v0.3.11 — one LZMA archive, Windows access, measured progress

**November 7, 2026**

Version 0.3.11 restores the original three-file archive workflow while retaining
live-thread snapshots. Default exports create one LZMA ZIP, with no review ZIP
or retained review directory. Windows publication now inherits the destination
folder's access rules, and progress covers the previously silent compression,
verification, and publication stages.

## Changes

- Restore ZIP/LZMA level 9, `dictionary=256m`, `word_size=64`, `threads=19`, and
  `backend=auto`. A compatible external 7-Zip CLI is selected for LZMA; saved
  explicit executable paths remain supported. Nineteen threads is a requested
  backend setting, not a promise of parallelism in every phase.
- Disable review output by default. Successful default cleanup leaves exactly
  one ZIP with rendered Markdown, its manifest, and captured native JSONL.
  Ordinary stdout/open-after selects that ZIP.
- Make `--review` add its guide, index, recent excerpt, and byte-preserving TXT
  parts inside the same archive. Persist `review` and `review_chunk_bytes` with
  the existing archive-default controls. Keep explicit `--review-from` conversion
  for callers who want a separate Deflate review ZIP and direct TXT directory.
  Honor `--no-archive` with a verified review directory only; no ZIP is created.
- Publish Windows files by exclusive fresh creation, bounded copying, SHA-256
  comparison, flush, and independent readback. Newly created files inherit the
  destination ACL. Staging/source/parent permissions and ownership are unchanged.
  POSIX keeps efficient hard links where available and verified-copy fallback.
- Add repeatable `--diagnose-access PATH` and `--repair-access PATH`. Diagnostics
  report actual read access, owner SID, DACL details, and parent permissions.
  Repair accepts only explicit recognized exports, resets inherited DACLs, and
  returns before/after results. It refuses broad directories, app sources,
  wildcards, links/junctions, and multiply linked files. It never takes ownership,
  grants Everyone access, invokes automatic elevation, or changes parent ACLs.
- Add `--progress-style auto|rich|plain|json|off` and preserve `--no-progress`.
  Terminal output includes bars, colors/icons where supported, elapsed time,
  measured rates, and ETA when meaningful. Redirected output is sparse plain
  text or explicit JSON events. Progress stays on stderr.
- Stream 7-Zip progress and drain its output continuously with bounded retained
  diagnostics. Show backend-reported percentages and members during compression;
  independent verification uses Python decoding and measured SHA-256 byte counts.
  Unknown denominators use activity/elapsed time. Cancel the child
  process on interruption. Separate snapshot, render, verify, publication, and
  cleanup stages; Windows publication separates checksum, copy, and readback.
- Reject generated-output paths that alias a source or another output, including
  symlinks/junctions and existing hard links. In particular, an explicit manifest
  cannot overwrite the live rollout or the rendered Markdown.
- Preserve the verified live-prefix contract from 0.3.9: ordinary append activity
  does not abort an export; detected truncation/rewrite/replacement during capture
  still fails safely. Native source hashes, complete-record handling, original
  provenance, independent ZIP verification, and collision protection remain.

## Why the permission change is separate from compression

A ZIP can be valid yet inaccessible to the process trying to open it. Python's
private temporary-directory ACL and an elevated Windows token can combine to
exclude the ordinary interactive user; [CPython issue #157876](https://github.com/python/cpython/issues/157876)
describes this behavior. The previous snapshot/review publication paths used
hard links or renames, which can retain that staging security descriptor.
Microsoft documents that [new files inherit parent ACLs, while moved files do
not receive a new default descriptor](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)
and [hard links share one file security descriptor](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createhardlinkw).

Fresh destination creation fixes that transfer without weakening private staging
or changing live rollouts. This is a code-grounded explanation for a matching
failure, not a claim that a particular user's ACL has already been measured.
The new diagnostics establish actual local state. A restrictive output parent
still needs separate attention: child inheritance cannot grant rights missing
from the parent. Explicit repair uses the documented [`icacls /reset`](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls)
operation and requires existing permission to change the selected DACL.

LZMA remains ZIP method 14. Python decodes it, while [some other extractors do
not](https://docs.python.org/3.13/library/zipfile.html#zipfile.ZIP_LZMA). The exporter
retains the requested LZMA policy and verifies actual decoded member bytes.
Successful decoding and permission checks do not establish complete model
attachment ingestion or eliminate model context limits.

## Upgrade and restore saved settings

Upgrade the Python interpreter used by the existing helper, then explicitly
restore preferences changed by earlier Deflate instructions:

```powershell
$py = Join-Path $env:LOCALAPPDATA 'Programs\Python\Python313\python.exe'
$archiver = 'C:\Program Files\7-Zip-Zstandard\7z.exe'
& $py -m pip install --upgrade --no-deps 'https://github.com/lowestprime/codex-exporter/releases/download/v0.3.11/codex_exporter-0.3.11-py3-none-any.whl'
if ($LASTEXITCODE -ne 0) { throw 'Exporter upgrade failed.' }
& $py -m codex_exporter `
    --set-archive-default archive=true `
    --set-archive-default "archiver=$archiver" `
    --set-archive-default backend=auto `
    --set-archive-default method=LZMA `
    --set-archive-default level=9 `
    --set-archive-default dictionary=256m `
    --set-archive-default word_size=64 `
    --set-archive-default threads=19 `
    --set-archive-default cleanup=true `
    --set-archive-default copy_source=true `
    --set-archive-default review=false
if ($LASTEXITCODE -ne 0) { throw 'Could not restore archive preferences.' }
& $py -m codex_exporter --version
& $py -m codex_exporter --show-archive-config
```

The [Windows upgrade guide](../WINDOWS-UPGRADE.md) includes interpreter/executable
checks, complete configuration validation, scoped repair examples, and standalone
script instructions. Package installation itself does not erase saved choices.
Use the release's actual `SHA256SUMS.txt` when pinning a built wheel; no digest is
inferred from a version number.

## Verification scope

Regression coverage includes default three-member and opt-in embedded-review
archives; captured-source consistency; LZMA and Deflate decoding; CRC/hash checks;
exclusive publication, failure cleanup, and collision preservation; exact review
reconstruction; structured progress and 7-Zip framing; and interrupted children.
Windows ACL tests create protected OWNER RIGHTS staging and a distinct output
parent ACL, verify destination inheritance and ZIP readback, and check that
repairs preserve source/parent security descriptors and owner identities.

The CI matrix targets Python 3.10 and 3.13 on Windows, macOS, and Linux, plus
package, PowerShell, and mirrored-module checks. Local Linux tests cannot prove
Windows ACL behavior; consult the tagged release's Actions results for actual
platform outcomes. Private user archives and credentials are not included in the
regression fixtures. Runtime, memory, and compression measurements depend on the
actual data and machine; no universal optimal encoder setting is asserted.
