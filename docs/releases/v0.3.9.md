# Codex Exporter v0.3.9 — verified live-thread snapshots

**November 6, 2026**

A running Codex rollout can grow while it is being exported. Versions through
0.3.8 detect that change and abort, forcing repeated attempts to find a quiet
window. Version 0.3.9 captures a bounded, verified source prefix first, so a live
thread can continue writing throughout rendering and ZIP creation.

## Changes

- Default live snapshots for all local Codex export modes, including automatic
  large-thread streaming. Existing `cdx-thread`, `cdx-project`, and other helpers
  require no new option.
- Fixed byte cutoff from an open file handle; a second bounded SHA-256 read verifies
  the captured prefix. Detected truncation, replacement, and rewriting during
  capture fail before rendering. Normal appends are allowed.
- Complete EOF records retained, including narrowly repairable JSON. Unfinished
  or invalid unterminated tails are deferred with explicit byte counts and hashes.
  Completed malformed records remain in the native copy and parse audit.
- One captured decoded JSONL feeds rendering, provenance, and archival source
  copying. Both manifest formats include capture timestamps, byte boundaries,
  hashes, encoding, and deferred-tail metadata while retaining the original path.
- Compressed sources decoded once; concatenated frames supported and incomplete
  Zstandard frames/checksums rejected.
- Private snapshots reused as native copies through exclusive hard links when
  supported, with a verified copy fallback. Buffered exports reuse the captured
  hash instead of repeatedly loading whole files for hashing.
- Final ZIP opened after packaging when requested; incompatible explicit fast
  options rejected before capture. All bundled Python modules are synchronized
  and checked as part of package validation.

Compression defaults, PowerShell helper signatures, output preferences, and the
0.3.8 dictionary-membership repair are preserved. ZIP member hash/size verification
still precedes loose-output cleanup; app-owned sources remain untouched.

## Install

Upgrade the interpreter that already runs your working 0.3.8 exporter:

```powershell
$py = Join-Path $env:LOCALAPPDATA 'Programs\Python\Python313\python.exe'
& $py -m pip install --upgrade --no-deps 'https://github.com/lowestprime/codex-exporter/releases/download/v0.3.9/codex_exporter-0.3.9-py3-none-any.whl'
if ($LASTEXITCODE -ne 0) { throw 'Exporter upgrade failed.' }
& $py -m codex_exporter --version
```

See the [Windows upgrade guide](../WINDOWS-UPGRADE.md) for configuration checks and
standalone-script installations. This release provides a wheel, source
distribution, and SHA-256 checksums. It does not require a PowerShell profile
replacement for existing package-routed helpers.

## Exact scope

An export contains the complete-record prefix captured for that invocation. It
cannot include future events appended after its cutoff. The checks establish a
verified append-only prefix, not an atomic filesystem snapshot against arbitrary
in-place writers. After capture, original-source changes cannot affect that
export's rendered content or native archived copy. Each batch source is captured
independently. See [manifest semantics](../INTEGRITY-AND-MANIFEST.md).
