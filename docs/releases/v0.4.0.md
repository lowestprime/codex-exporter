# Codex Exporter v0.4.0

Large live sessions could exceed the upload ceiling, subset exports still included
unrelated historical JSONL, and the interactive chooser's progress heartbeat could
obscure its prompt. This release fixes those paths while retaining configured LZMA
compression and verified snapshots of running threads.

- Enforce a 512,000,000-byte maximum for every published ZIP, including metadata.
  Reuse already-compressed members, split oversized members losslessly, and publish
  independently readable parts with byte-offset/SHA-256 reconstruction metadata.
- Bundle multi-session/project exports into one bounded set by default. Preserve
  per-session manifests and a batch index; `--separate-archives` restores separate
  session archives. Normal single-session fitting exports retain the three files.
- Add inclusive `--since` / `cdx-since` selection by prompt text, user-turn number,
  native ID or offset-aware timestamp, with explicit ambiguity handling and
  `--list-turns` / `cdx-turns` discovery.
- Retain exact matching native JSONL excerpts for subset exports, including merged
  tool-call/output provenance. Stream since/last-N selections without rendering
  old history. Preserve complete raw selected events and disclose embedded history.
- Replace the browser with stderr-only, width-aware interaction, cross-page
  selection, previews, search, sorting, availability filters and clean cancellation.
- Fix shell argument forwarding, outdated-script routing, standalone module
  installation, and profile loader order. Preserve explicit interpreter/script
  overrides and existing archive preferences.

Every bounded archive is fully decoded and verified before publication and cleanup.
Windows destination-permission handling and live-source protection are retained.
No silent compression-method downgrade is introduced.

## Behavior changes

- Bundled multi-session JSON results contain `archives`, `archive_parts` and
  `exports`; `--separate-archives` retains per-session results.
- Subset source hashes now refer to the included native excerpt; original snapshot
  hashes and byte mappings remain in the selection manifest.
- Oversized exports produce multiple ordinary `.zip` files; no exported ZIP can
  opt out of the hard ceiling. Smaller ceilings are configurable.

## Compatibility scope

A valid ZIP below the file-size cap is not proof of remote upload materialization,
codec availability, complete reading, or context ingestion. LZMA/9/256m/64/19 remains
the normal profile; no universal best compression ratio/speed claim is made.

See [bounded exports and selection](../BOUNDED-EXPORTS-AND-SELECTION.md) for examples,
reconstruction rules, browser controls and the exact scope of the guarantees.
