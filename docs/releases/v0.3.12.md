# v0.3.12 — Diagnose ZIP availability and decoding independently

A receiving runtime can report an unavailable attachment even when its ZIP/LZMA
contents are valid. This release adds a read-only diagnostic path so file access,
codec support, dictionary requirements, and full integrity are not conflated.

## Changes

- Add repeatable `--diagnose-archive PATH`, `--archive-check full|metadata`, and an
  explicit `--archive-max-dictionary-mib` diagnostic guard.
- Report current-runtime capabilities, archive size/hash, exact member inventory,
  actual ZIP-LZMA properties, decoded CRC/size/hash results, and concrete failures.
- Provide the same reader as a standalone standard-library script, with no
  exporter installation required.
- Detect input changes during inspection, malformed/overlapping LZMA headers,
  unsafe names, duplicate names, encrypted members, and unsupported codecs without
  extracting or executing archive contents.
- Document a receiving-runtime verification sequence and honest memory/compatibility
  boundaries; correct stale compatibility documentation from the 0.3.10 defaults.

## Preserved behavior

The normal archive/render/snapshot/publication/progress modules are unchanged.
LZMA level 9, dictionary 256m, word size 64, 19 requested threads, the single
three-member ZIP, opt-in embedded review, Windows inheritance, and live snapshots
retain their existing behavior. Diagnostics run only when requested. Installing
this release preserves saved preferences.

This release does not claim to fix a remote file-delivery service, certify an
unobserved ChatGPT runtime, or require recompressing existing valid archives.
See [Archive diagnostics](../ARCHIVE-DIAGNOSTICS.md).
