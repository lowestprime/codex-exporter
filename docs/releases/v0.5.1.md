# Codex Exporter 0.5.1

## Correct success reporting after recovered compression attempts

A compression candidate that exceeds its planning budget is now reported as a
retry. A successfully verified and published export ends successfully even when
a prior candidate needed a smaller range. Genuine encoder, verification,
publication, cleanup and cancellation failures remain failures. JSON progress
includes explicit retry and settled-stage counts.

## Better large-member planning

Bounded stratified probes sample across large members instead of relying only on
the beginning. Regional estimates and completed-range measurements guide later
boundaries. Final size limits, native bytes, complete CRC/SHA-256 reconstruction,
compressed-stream reuse and the measured packing algorithm remain authoritative.
The default LZMA settings and all saved preferences are retained.

## Consistent final-record selection

`cdx-turns` and export snapshots now share the same EOF completeness policy.
Complete repairable final records remain visible without a newline; incomplete
JSON or UTF-8 tails remain deferred. Original source bytes are not modified.

## Additional lifecycle fixes

- Final summaries follow required output handling and resource cleanup.
- Candidate-removal errors preserve the primary diagnostic and block unsafe retries.
- Compressor subprocesses are reaped if helper-thread startup fails.
- Relative compression paths are resolved before changing the child directory.
- Canonical, packaged and bundled skill copies stay synchronized.

## Validation

All seven initial CI jobs passed: Python 3.10/3.13 on Windows, Linux and macOS,
plus packaging. The implementation passed 635 tests per Windows job and 636 per
Linux/macOS job, with only the declared platform/optional skips. Synthetic
real-codec benchmarks include all 12 runs, exact source identities, full
reconstruction checks and a standalone reproduction harness. Both selected cases
kept two parts and required zero rejected candidates after this change; archive
size changes were +34 bytes and -58 bytes respectively. Timing results are
workload-specific measurements from a shared runner.
